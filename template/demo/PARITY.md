# Surface parity ledger

One backend, two clients. Every tRPC action the API exposes must be **accounted for** on
each surface — surfaced by a screen, or deliberately exempt with a stated reason. This file
is that ledger, and the `parity` gate (`tools/check-mobile-parity.mjs`) holds it honest:

- **Exactly one row per action.** The actions are the committed inventory at
  `tools/generated/action-inventory.json` (regenerated by `pnpm gen`, kept fresh by the
  `contracts` gate). A new action with no row here **reds** parity; a row for a
  deleted/renamed action **reds** parity too (the closure runs both ways).
- **Each surface cell is a repo-relative screen path that exists, or `—`** (exempt). A
  path that names a missing file reds. An `—` on any surface **requires a reason** in the
  Notes cell — an exemption is a decision, and a decision carries its why.
- This ledger is **seeded, not owned**: it names *this* project's screens, so tune it as you
  build. Adding an action? Add its row in the same change (see `.claude/skills` /
  `docs/architecture`). The gate ships **soft** for installs that predate it and **strict**
  for fresh installs and the template — force strict anywhere with
  `CHECK_MOBILE_PARITY_STRICT=1`.

Each row is one procedure the router mounts, with the screen that surfaces it on each side; a
`—` cell carries its reason. The system procedures come with every scaffold, and a vertical
brings its own rows (the notes vertical `init --with-demo` plants is the worked example, with
five).
